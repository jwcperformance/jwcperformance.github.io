Is Your Website Invisible to AI Search? How to Check, and How to Fix It

More people now ask ChatGPT, Google's AI and other tools to recommend a business. But some websites are built in a way those tools can't fully read. Here's what a recent test found, how to check your own site in five minutes, and what to fix if pages are missing.

What the test found

SEO engineer Vinicius Stanula ran a 41 day test on a site with around 1,000 pages. Some sections were linked with normal HTML links. Others were only linked through JavaScript, which means the links only appeared after code ran in the browser.

The results were clear. AI crawlers like GPTBot, ClaudeBot and PerplexityBot didn't find a single page in the sections linked only by JavaScript. Googlebot did reach them, though it struggled deeper into the site. When the links were switched to plain HTML, GPTBot found 250 new pages within 48 hours.

Why this happens

When you visit a website, your browser downloads the page and then runs any code that comes with it. That code can build menus, load text and add links. Google's crawler can do the same thing, although it takes longer.

Most AI crawlers don't. A 2024 study by the hosting company Vercel found that none of the major AI crawlers it tracked, including those from OpenAI, Anthropic and Perplexity, ran JavaScript. They read the page as it first arrives from the server. If a link or a paragraph isn't there yet, they don't see it.

So if your menu, your service pages or your main text only appear once code runs, AI tools may not know those pages exist. And if they can't see them, they can't recommend you for those jobs.

Why it matters for local businesses: When someone asks an AI tool "who's a good electrician in Bromley?", the tool can only suggest businesses it understands. A website it can't read properly gives it very little to go on. I covered this from the Google side in my post on staying in Google's AI local results.

Which websites are most at risk?

Plenty of sites are fine. The ones to check most carefully are:

  • Sites with fancy menus that open, slide or load on click, especially if the links inside them aren't normal links.
  • Sites built as "apps" with some modern JavaScript frameworks, where the whole page is built in the browser.
  • Pages that load more content as you scroll, or hide text behind tabs and "read more" buttons that pull it in later.
  • Sites with text inside images, like a banner with your services written on it. No crawler can read that as text.

How to check your own site

You don't need special tools. Do this on a computer.

1. View the page source

Open your homepage and press Ctrl and U, or Cmd, Option and U on a Mac. This shows the raw page as it arrives from your server, before any code runs. It's roughly what most AI crawlers see.

2. Look for your service page links

Press Ctrl and F and search for the address of one of your service pages, like "/boilers". If it's there inside an a href link, that page can be found. If it isn't there at all, the link is probably being added by code.

3. Look for your main text

Copy a sentence from the page, like your opening line, and search for it in the source. If you can't find it, that text is being loaded later, and AI tools may not see it.

4. Check your robots.txt

Visit yoursite.co.uk/robots.txt. This file tells crawlers what they're allowed to read. Make sure it isn't blocking the AI tools you want to appear in. Some security services also have settings that block AI crawlers, so check those too. One thing to know: blocking OpenAI's GPTBot stops your content being used for training, while ChatGPT's search uses a separate crawler called OAI-SearchBot.

How to fix it

  • Use real HTML links for your menu and your service pages. Every important page should be reachable through normal links in the page source.
  • Put key content in the page itself. Your services, areas, prices and FAQs should be in the page as text when it loads, not pulled in afterwards.
  • Ask about server side rendering if your site is built with a JavaScript framework. It means the server sends the finished page, so crawlers see everything straight away.
  • Keep an up to date sitemap so search engines have a full list of your pages.
  • Replace text in images with real text on the page.

If your site has bigger technical problems too, my post on what actually stops a site ranking covers the other common culprits.

Why simple often wins

The sites that do best here are often the simplest. Plain pages, real links and clear text, loading fast. That's the same thing that makes a site quick on a phone and easy for customers to use. My post on what a trade website needs in 2026 covers the rest of the checklist.

It's also how I build websites. The pages are plain HTML with real links and real text, so Google, AI tools and customers all see the same thing.

Common questions

Can ChatGPT read my website?

It can read text and links that are in your page when it first loads. Studies have found that AI crawlers, including OpenAI's, don't run JavaScript, so content or links added by code afterwards may be missed.

Can Google see JavaScript links?

Usually, yes. Googlebot can run JavaScript, and it reached JavaScript linked pages in the test. But it found fewer pages deeper in the site, so plain HTML links are still the safest choice.

How do I know if my site uses JavaScript links?

View the page source with Ctrl and U and search for one of your page addresses. If it isn't there inside a normal link, the link is probably being added by code.

Should I block AI crawlers?

That's your choice. If you want AI tools to recommend your business, don't block the crawlers they use to read websites. You can still block training crawlers separately if you prefer.

The bottom line

If AI tools can't read your website, they can't recommend you. The fix is usually simple: real links, real text in the page, and no accidental blocks. Check your page source today.
